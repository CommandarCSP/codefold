# 직접 해 보는 테스트 시나리오

배포한 사이트에서 사람이 직접 따라 하며 확인하는 시나리오입니다. 자동 E2E 테스트(`apps/zip-editor/e2e/`)와 같은 기능을 사용자가 앱을 쓰는 순서대로 묶었습니다. 화면의 느낌, Safari에서의 동작, 실제 끌어 놓기처럼 자동 테스트로 확인하기 어려운 것도 넣었습니다.

## 준비

1. **최신 버전으로 배포합니다.** 저장소 루트에서 `pnpm deploy:prod`를 실행합니다([ADR-0043](adr/0043-manual-prebuilt-deploy.md) 참고). 커밋하지 않은 변경이 있으면 배포 스크립트가 배포를 멈추므로 먼저 모두 커밋해 둡니다. Vercel CLI에는 계정 주인으로 로그인해 두어야 합니다(`npx vercel@latest login`). 커밋 작성자가 Vercel 계정 주인과 달라서 git 연동 자동 배포와 Vercel 대시보드의 **Redeploy**는 막힙니다. 배포가 끝나면 https://codefold-zip-editor.vercel.app 을 엽니다.
2. **샘플 ZIP을 만듭니다.** 저장소 루트에서 `pnpm --filter @codefold/zip-editor samples`를 실행하면 `apps/zip-editor/samples/`에 아래 파일이 생깁니다.

| 파일 | 들어 있는 것 |
|---|---|
| `basic.zip` | `src/main.py`, `src/util.py`, `README.md`, `data/input.txt`, PNG 이미지, 스크립트가 든 SVG, 바이너리 `bin/app.bin`, 지울 폴더 `legacy/`, 한글 이름 파일, 빈 폴더, 맥 부가 파일(`__MACOSX/`, `.DS_Store`) |
| `images.zip` | 눈에 보이는 이미지 여러 개: 로고·체크 무늬 PNG, 화면보다 넓은 PNG, 반투명 PNG, BMP, SVG, 확장자만 PNG인 텍스트 파일 `not-really.png` |
| `ts-project.zip` | 서로 import하는 TS 파일 두 개(`src/index.ts`, `src/price.ts`), CSS, HTML, JSON, 한 줄이 아주 긴 텍스트 |
| `euc-kr.zip` | EUC-KR로 저장한 한국어 텍스트 파일 |
| `large-10000.zip` | 폴더 100개에 파일 100개씩, 모두 1만 개 |
| `not-a-zip.zip` | 이름만 `.zip`인 텍스트 파일 |

3. 앞선 테스트에서 브라우저에 자동 저장된 작업이 남아 있으면 결과가 섞입니다. 시나리오를 시작할 때 복원 안내가 뜨면 **버리기**를 누릅니다.

## 1. 첫 화면과 업로드

**1-1. 첫 화면**
- 순서: 사이트를 엽니다.
- 기대 결과
  - [ ] 위쪽에 "ZIP 에디터" 제목, **ZIP 올리기**, 꺼진 **다운로드** 버튼이 있습니다.
  - [ ] 가운데에 "ZIP 파일을 올려 주세요" 안내가 있습니다.

**1-2. 파일 골라 업로드**
- 순서: **ZIP 올리기**를 눌러 `basic.zip`을 고릅니다.
- 기대 결과
  - [ ] 왼쪽 트리에 최상위 항목만 보입니다. 폴더가 먼저 오고 그다음 파일이 옵니다. 폴더와 파일은 각각 이름순입니다.
  - [ ] `__MACOSX`, `.DS_Store`는 보이지 않습니다.
  - [ ] `한글 이름 문서.txt`의 이름이 깨지지 않고 보입니다.
  - [ ] `src` 폴더를 누르면 펼쳐지고, 한 번 더 누르면 접힙니다.

**1-3. 끌어 놓기**
- 순서: Finder에서 `ts-project.zip`을 브라우저 창에 끌어 놓습니다. 이어서 ZIP 두 개를 함께 끌어 놓아 봅니다.
- 기대 결과
  - [ ] 끌고 있는 동안 "놓으면 이 ZIP을 엽니다" 안내가 화면을 덮습니다.
  - [ ] 놓으면 새 ZIP이 열립니다.
  - [ ] 두 개를 놓으면 화면 아래 가운데에 "ZIP 파일 하나만 놓아 주세요."만 뜨고, 열려 있던 작업은 그대로입니다.

**1-4. ZIP이 아닌 파일**
- 순서: `not-a-zip.zip`을 업로드합니다. 안내가 뜨면 안내 오른쪽의 × 버튼("알림 닫기")을 누릅니다.
- 기대 결과
  - [ ] "ZIP 파일이 아니에요. 다른 파일을 골라 주세요."가 보이고, 열려 있던 작업 공간은 그대로입니다.
  - [ ] 안내는 화면 아래 가운데에 떠 있습니다. 안내가 생기고 사라질 때 트리와 에디터가 밀려 움직이지 않습니다.
  - [ ] × 버튼을 누르기 전에는 시간이 지나도 안내가 남아 있고, 누르면 사라집니다.

## 2. 파일 열기와 보기

**2-1. 텍스트 파일**
- 순서: `basic.zip`에서 `src/main.py`를 누릅니다.
- 기대 결과
  - [ ] 탭이 생기고 Python 문법에 따라 글자 색이 칠해진 에디터가 열립니다.

**2-2. 이미지와 바이너리**
- 순서: `images/logo.png`, `images/icon.svg`, `bin/app.bin`을 차례로 엽니다.
- 기대 결과
  - [ ] PNG(보라색 원 로고)와 SVG가 이미지로 보입니다.
  - [ ] SVG를 열어도 그 안의 스크립트가 띄우는 알림창("실행되면 안 됨")이 뜨지 않습니다.
  - [ ] SVG 화면의 **코드로 보기**를 누르면 SVG 코드를 수정할 수 있습니다.
  - [ ] `app.bin`을 열면 "편집할 수 없는 파일이에요" 안내와 파일 크기, 앱이 바이너리로 분류한 근거가 보입니다.

**2-3. 여러 이미지 형식**
- 순서: `images.zip`을 업로드하고 파일을 하나씩 엽니다.
- 기대 결과
  - [ ] `logo.png`, `photo.png`, `alpha.png`, `banner.bmp`, `icon.svg`가 모두 이미지로 보입니다.
  - [ ] 가로 2400px인 `wide.png`는 창 폭에 맞춰 줄어들어 전체가 보입니다.
  - [ ] `alpha.png`는 왼쪽으로 갈수록 투명해져 뒤 배경이 비칩니다.
  - [ ] `not-really.png`는 "확장자(png)와 달리 내용은 텍스트 파일로 보여요." 안내와 함께 에디터로 열립니다.

**2-4. EUC-KR 파일**
- 순서: `euc-kr.zip`을 업로드하고 `옛날 문서.txt`를 엽니다.
- 기대 결과
  - [ ] 한국어가 깨지지 않고 보이고, "EUC-KR로 추정되는 파일이라 읽기 전용으로 열었어요." 안내가 보입니다.
  - [ ] 안내에 있는 **UTF-8로 바꿔 편집**을 누르면 수정할 수 있습니다.

**2-5. 여러 파일 자동 완성**
- 순서: `ts-project.zip`을 업로드하고 `src/price.ts`, `src/index.ts`를 엽니다. `index.ts` 첫 줄의 `{ formatPrice }`에서 `formatPrice` 뒤에 `, CUR`를 입력합니다.
- 기대 결과
  - [ ] 자동 완성 목록에 `price.ts`가 내보내는 `CURRENCY`가 나옵니다.
  - [ ] `formatPrice` 위에 마우스를 올리면 함수 타입이 보입니다.

## 3. 수정, undo, 다운로드

**3-1. 수정 표시**
- 순서: `basic.zip`의 `src/main.py` 끝에 `# 수정`을 입력합니다.
- 기대 결과
  - [ ] 탭과 트리의 `main.py`, 부모 폴더 `src`에 수정 표시가 붙습니다.
  - [ ] **다운로드** 버튼이 켜지고, 위쪽에 "받지 않은 변경 1개"가 보입니다.

**3-2. undo와 redo**
- 순서: 이어서 Cmd+Z(Windows는 Ctrl+Z)를 누른 뒤, Cmd+Shift+Z(Ctrl+Shift+Z)를 누릅니다.
- 기대 결과
  - [ ] undo하면 원본과 같아져 수정 표시가 사라지고 **다운로드**가 꺼집니다.
  - [ ] redo하면 수정 표시가 다시 붙습니다.

**3-3. 다운로드하고 다시 올리기**
- 순서: `main.py`를 수정한 상태에서 **다운로드**를 누릅니다. 다운로드한 ZIP을 다시 업로드합니다.
- 기대 결과
  - [ ] 다운로드한 ZIP의 이름이 원래 이름(`basic.zip`)과 같습니다.
  - [ ] 다시 올리면 `main.py`에 수정한 내용이 있습니다.
  - [ ] 다운로드한 ZIP을 Finder에서 풀면 이미지·바이너리가 원본과 같고, 빈 폴더도 남아 있습니다.

**3-4. 다운로드 뒤 받지 않은 변경**
- 순서: 다운로드한 뒤 다른 파일(`src/util.py`)을 수정합니다.
- 기대 결과
  - [ ] "받지 않은 변경 1개"가 다시 보입니다. `main.py`는 여전히 "수정됨"이지만 받지 않은 변경에는 들어가지 않습니다.

## 4. 트리 조작

**4-1. 새 파일**
- 순서: `src` 폴더를 고른 뒤 트리 위의 새 파일 버튼을 누릅니다. 이름 칸에 `new.py`를 입력하고 Enter를 누릅니다.
- 기대 결과
  - [ ] `src` 안에 `new.py`가 생기고 탭이 열립니다.
  - [ ] **에디터를 누르지 않아도 바로 글자를 입력할 수 있습니다.**
  - [ ] 이름을 입력하는 중에 Esc를 누르면 파일이 만들어지지 않습니다.

**4-2. 이름 규칙**
- 순서: 새 파일 이름에 이미 있는 이름(`main.py`)이나 `/`가 든 이름을 입력합니다.
- 기대 결과
  - [ ] 입력칸 아래에 만들 수 없는 이유가 보이고, 파일은 만들어지지 않습니다. 이 안내가 트리 다음 줄의 글자와 겹쳐 보이지 않습니다.

**4-3. 이름 바꾸기와 지우기**
- 순서: 수정한 `main.py`가 탭에 열린 상태에서 이름을 `app.py`로 바꿉니다. 이어서 `legacy` 폴더를 지웁니다. 마지막으로 `src` 폴더를 지우려다 확인창에서 **취소**합니다.
- 기대 결과
  - [ ] 탭 제목이 `app.py`로 바뀌고 수정 표시가 그대로 따라갑니다.
  - [ ] 수정한 파일이 없는 `legacy`는 확인창 없이 바로 지워지고, 그 안 파일을 열어 둔 탭이 있으면 그 탭도 닫힙니다.
  - [ ] 수정한 파일(`app.py`)이 든 `src`를 지우려 하면 "수정한 파일이 함께 지워져요" 확인창이 뜹니다. **취소**하면 `src` 폴더와 그 안 파일이 그대로 남습니다.

**4-4. 변경 되돌리기**
- 순서: 트리에서 수정한 파일을 오른쪽 클릭해 **변경 되돌리기**를 고릅니다.
- 기대 결과
  - [ ] 확인창에서 확인하면 파일이 원본 내용으로 돌아가고 수정 표시가 사라집니다.

## 5. 탭과 화면 나누기

**5-1. 탭 끌어 나누기**
- 순서: 파일 두 개를 연 뒤, 한 탭을 끌어 에디터 영역 오른쪽 가장자리에 놓습니다.
- 기대 결과
  - [ ] 에디터 영역이 좌우로 나뉘고, 두 그룹에 에디터가 하나씩 보입니다.

**5-2. 크기 조절**
- 순서: `ts-project.zip`의 `long-line.txt`를 나눈 화면에 열고, 두 그룹 사이 경계를 끌어 옮깁니다.
- 기대 결과
  - [ ] 경계를 옮기는 대로 에디터 폭이 바뀌고 글자가 새 폭에 맞춰 다시 그려집니다.

**5-3. 두 그룹에서 같은 파일**
- 순서: 탭 줄 오른쪽의 **오른쪽으로 나누기** 버튼으로 같은 파일을 두 그룹에 엽니다. 한쪽에서 입력하고 undo합니다.
- 기대 결과
  - [ ] 입력한 내용이 양쪽에 같이 보이고, undo도 양쪽에 반영됩니다.

**5-4. 탭 닫았다 다시 열기**
- 순서: 수정한 파일의 탭을 닫고 트리에서 다시 엽니다. 이어서 undo합니다.
- 기대 결과
  - [ ] 닫은 동안에도 트리에 수정 표시가 남습니다.
  - [ ] 다시 열면 수정한 내용이 보이고, undo하면 원본으로 돌아갑니다.

**5-5. 활성 탭 표시**
- 순서: 화면을 두 그룹으로 나눈 상태에서 왼쪽 그룹의 탭과 오른쪽 그룹의 탭을 번갈아 누릅니다.
- 기대 결과
  - [ ] 그룹마다 활성 탭의 위쪽 가장자리에 가는 선이 있습니다.
  - [ ] 지금 누른 그룹의 활성 탭 선은 눈에 띄는 색이고, 다른 그룹의 활성 탭 선은 흐린 색입니다. 누르는 그룹을 바꾸면 두 선의 색도 서로 바뀝니다.

**5-6. 떠 있는 창 없음** (ADR-0042)
- 순서: 그룹 머리 오른쪽의 버튼을 살펴봅니다. 이어서 Shift를 누른 채 탭을 끌어 에디터 영역 가운데에 놓아 봅니다.
- 기대 결과
  - [ ] 그룹 머리의 버튼은 **오른쪽으로 나누기** 하나뿐이고, "창으로 띄우기" 버튼은 없습니다.
  - [ ] Shift를 누른 채 끌어도 에디터 위에 떠 있는 창이 생기지 않습니다.

## 6. 자동 저장과 복원

**6-1. 새로고침 뒤 이어 하기**
- 순서: 파일을 수정하고, 파일 하나를 새로 만들고, 화면을 나눕니다. 2초쯤 기다린 뒤 새로고침합니다.
- 기대 결과
  - [ ] "이전 작업을 이어서 할까요?" 안내가 ZIP 이름, 마지막 수정 시각과 함께 **떠 있는 창으로** 보입니다. 뒤 화면은 흐립니다.
  - [ ] 안내가 떠 있어도 위쪽 **ZIP 올리기**를 누를 수 있습니다.
  - [ ] **이어 하기**를 누르면 수정한 내용, 새 파일, 나눈 화면이 되살아납니다.
  - [ ] undo 기록은 되살아나지 않습니다(Cmd+Z를 눌러도 새로고침 전으로 돌아가지 않습니다).

**6-2. 버리기**
- 순서: 새로고침한 뒤 **버리기**를 누릅니다.
- 기대 결과
  - [ ] 첫 화면으로 돌아가고, 다시 새로고침해도 안내가 뜨지 않습니다.

**6-3. 브라우저를 닫았다 열기**
- 순서: 수정한 뒤 2초쯤 기다렸다가 브라우저 창을 완전히 닫고 다시 엽니다.
- 기대 결과
  - [ ] 복원 안내가 뜨고, **이어 하기**를 누르면 마지막 수정까지 되살아납니다.

**6-4. 떠날 때 경고**
- 순서: 입력하자마자 새로고침합니다. 다음에는 입력하고 2초 넘게 기다린 뒤 새로고침합니다.
- 기대 결과
  - [ ] 곧바로 새로고침하면 브라우저가 떠날지 묻는 창을 띄웁니다.
  - [ ] 2초 넘게 기다렸으면(저장이 끝났으면) 묻지 않고 새로고침됩니다.

**6-5. 새 ZIP으로 바꾸기**
- 순서: 받지 않은 변경이 있는 상태에서 다른 ZIP을 업로드합니다.
- 기대 결과
  - [ ] 바꿀지 묻는 확인창이 뜹니다. 취소하면 그대로이고, 확인하면 새 ZIP으로 바뀝니다.

**6-6. Cmd+S**
- 순서: 파일을 열고 에디터에서 Cmd+S(Windows는 Ctrl+S)를 누릅니다.
- 기대 결과
  - [ ] 브라우저의 페이지 저장 창이 뜨지 않습니다.
  - [ ] 화면 아래 가운데에 "변경 내용은 자동으로 저장됩니다"가 2초쯤 보였다가 저절로 사라집니다. 이 안내에는 × 버튼이 없습니다.

## 7. 편집 잠금 (브라우저 탭 두 개)

**7-1. 두 번째 탭**
- 순서: 작업 중인 사이트를 브라우저 새 탭에서 한 번 더 엽니다.
- 기대 결과
  - [ ] 새 탭에는 트리와 에디터 없이 화면 가운데에 카드 하나만 보입니다. 카드에는 "다른 탭에서 작업 중이에요" 제목, "편집은 한 번에 브라우저 탭 하나에서만 할 수 있어요. 여기서 열면 다른 탭은 읽기 전용이 돼요." 설명, **여기서 열기** 버튼이 있습니다.
  - [ ] 위쪽 막대의 **ZIP 올리기**와 **다운로드**는 꺼져 있습니다.
  - [ ] **여기서 열기**를 누르면 새 탭에서 편집하게 되고, 처음 탭은 "다른 탭으로 편집이 넘어갔어요" 안내와 함께 읽기 전용이 됩니다.

**7-2. 편집 중인 탭을 닫기**
- 순서: 두 탭이 열린 상태에서 편집 중인 탭을 닫습니다.
- 기대 결과
  - [ ] 남은 탭의 카드가 "이제 이 탭에서 편집할 수 있어요" 제목과 "편집하던 탭이 닫혀서 편집 권한이 이 탭으로 넘어왔어요." 설명으로 바뀝니다. **편집 시작**을 눌러야 편집 화면이 됩니다.

**7-3. 편집 시작 전에 잠금을 잃기**
- 순서: 같은 사이트를 브라우저 탭 세 개(A, B, C)에 차례로 엽니다. A가 편집 중일 때 A를 닫아 B에 "이제 이 탭에서 편집할 수 있어요" 카드가 뜨게 합니다. B에서 **편집 시작**을 누르지 않은 채 C에서 **여기서 열기**를 누릅니다.
- 기대 결과
  - [ ] C가 편집 화면이 됩니다.
  - [ ] B에는 다시 "다른 탭에서 작업 중이에요" 카드와 **여기서 열기** 버튼이 보입니다. "다른 탭으로 편집이 넘어갔어요" 읽기 전용 안내는 뜨지 않습니다.

## 8. 큰 ZIP

**8-1. 파일 1만 개**
- 순서: `large-10000.zip`을 업로드합니다. 트리를 끝까지 스크롤해 `d099` 폴더의 `f0099.ts`를 엽니다. 이 파일을 수정하고 다운로드합니다.
- 기대 결과
  - [ ] 업로드한 뒤 1초 안팎에 트리가 보입니다.
  - [ ] 스크롤과 입력이 끊기지 않습니다.
  - [ ] 다운로드는 몇 초 걸릴 수 있습니다. [성능 보고서](performance-report.md)에 개선 후보로 적어 둔 부분입니다. 다운로드한 ZIP을 다시 올리면 수정한 내용이 있습니다.

1GB가 넘는 ZIP에서 뜨는 경고("메모리가 부족하면 다운로드가 실패할 수 있어요")와 다운로드 실패 알림("ZIP을 만들지 못했어요")은 그런 ZIP을 만들기 어려워 이 시나리오에서 뺐습니다.

## 9. 화면과 접근성

**9-1. 테마**
- 순서: 오른쪽 위 테마 버튼으로 **라이트**, **다크**, **시스템**을 차례로 고릅니다.
- 기대 결과
  - [ ] 화면과 에디터 색이 함께 바뀌고, 새로고침해도 고른 테마가 남습니다.

**9-2. 좁은 화면**
- 순서: 브라우저 창 폭을 휴대폰만큼 줄입니다.
- 기대 결과
  - [ ] 트리가 접히는 패널이 되고, 왼쪽 위의 폴더 아이콘 버튼("파일 트리 열기")으로 열 수 있습니다. 파일을 고르면 패널이 닫힙니다.

**9-3. 키보드만으로**
- 순서: 마우스를 쓰지 않고 Tab으로 **ZIP 올리기**까지 가서 업로드합니다. 트리에서 방향키로 파일을 골라 Enter로 엽니다.
- 기대 결과
  - [ ] 포커스가 어디 있는지 눈에 보입니다.
  - [ ] 트리에서 위아래 방향키로 이동하고, 오른쪽·왼쪽 방향키로 폴더를 펼치고 접습니다.

**9-4. Safari**
- 순서: Safari에서 1-2, 3-1, 3-3, 6-1을 한 번씩 해 봅니다.
- 기대 결과
  - [ ] Chrome과 같게 동작합니다. SVG도 보입니다.

**9-5. 휴대폰 폭의 위쪽 막대와 에디터**
- 순서: 브라우저 창 폭을 휴대폰만큼(400px 안팎) 줄입니다. `basic.zip`을 올리고 `src/main.py`를 열어 한 글자 입력합니다.
- 기대 결과
  - [ ] 입력한 뒤에도 위쪽 막대가 화면 폭 안에 들어가고, 가로 스크롤이 생기지 않습니다.
  - [ ] **ZIP 올리기**와 **다운로드**는 글자 없이 아이콘만 보입니다.
  - [ ] 받지 않은 변경 배지에는 "받지 않은 변경 1개" 대신 숫자 `1`만 보입니다.
  - [ ] 에디터 오른쪽에 미니맵(코드 전체를 줄여 보이는 띠)이 없습니다.
  - [ ] 탭 줄 오른쪽에 **오른쪽으로 나누기** 버튼이 없습니다.
  - [ ] 창 폭을 다시 넓히면 버튼 글자, 배지 문구, 미니맵, 나누기 버튼이 다시 보입니다.
