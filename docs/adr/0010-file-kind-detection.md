# ADR-0010. 파일 종류 판단을 독립 패키지로 두고 단계별로 판단한다

- 상태: 승인 (일부 대체: 0023, 0031)
- 날짜: 2026-09-27

## 배경

ZIP 안의 파일 중 이미지는 바로 화면에 보여 주고, 편집할 수 있는 텍스트는 에디터로 연다. 그러려면 **어떤 파일이 바이너리인지, 편집할 수 있는 텍스트인지 판단해야** 한다.

판단은 정확해야 하고, 1만 개가 넘는 ZIP에서도 비용이 작아야 한다.

## 결정

파일 종류는 두 시점에 따로 판단한다. 트리를 그릴 때는 확장자만 보고, 파일을 열 때 내용까지 본다.

### 판단 시점

- 파일 트리 아이콘은 **확장자만** 보고 정한다. 모든 파일의 압축을 풀지 않는다.
- 실제 판단은 **파일을 열 때** 한다. 판단에는 앞 8KB만 필요하므로 `DecompressionStream`으로 앞부분만 풀고, 바이너리로 나오면 나머지는 풀지 않는다. 텍스트나 이미지면 전체를 푼다.

### 판단 순서

먼저 걸리는 단계에서 끝난다.

1. **magic bytes**: 앞 16바이트 이하를 서명 표와 비교한다. 이미지 서명이면 이미지, 그 밖의 바이너리 서명이면 바이너리다. 글자로 된 서명(`%PDF`, `GIF8` 등)을 텍스트로 오판하지 않도록 가능하면 제어 문자를 포함한 전체 서명으로 비교한다(예: ZIP은 `PK\x03\x04`).
2. **확장자**: 확장자가 이미지(png, jpg, gif, webp, bmp, ico, avif)면 이미지로, 알려진 바이너리(exe, woff, mp3, pdf 등)면 바이너리로 판정한다. SVG는 이미지로 보여 주되 "코드로 보기"로 전환해 편집할 수 있다. 확장자가 없거나 모르는 확장자면 다음 단계로 간다.
3. **내용 검사 (앞 8KB)**
   1. UTF-16 BOM(`FF FE`/`FE FF`)이 있으면 UTF-16 텍스트다. NUL 검사보다 먼저 확인한다.
   2. NUL 바이트가 있으면 바이너리다.
   3. `TextDecoder('utf-8', { fatal: true })`로 읽히면 UTF-8 텍스트다. 8KB 경계에서 잘린 멀티바이트 글자는 빼고 검사한다.
   4. UTF-8이 아니고 EUC-KR로 읽었을 때 대체 문자(`U+FFFD`)가 없고 한글 비율이 충분하면 **EUC-KR 추정 텍스트**다.
   5. 그 외는 바이너리다.
4. **크기 확인**: 텍스트여도 기준 크기를 넘으면 Monaco 일부 기능이 꺼진다는 안내와 함께 연다.

확장자와 내용이 충돌하면 **내용을 믿고**, 화면에 충돌 사실을 알린다(예: "확장자는 .txt지만 PNG 이미지입니다"). 빈 파일(0바이트)은 편집 가능한 텍스트로 본다.

### EUC-KR 처리

브라우저는 EUC-KR을 읽을 수 있지만 EUC-KR로 인코딩하는 API가 없다(`TextEncoder`는 UTF-8 전용).

| 선택지 | 판단 |
|---|---|
| A. 읽기 전용으로 열고, 사용자가 원하면 UTF-8로 변환해 편집 | **채택.** 사용자 모르게 인코딩이 바뀌지 않는다 |
| B. 편집 가능하게 열고 다운로드 때 UTF-8로 저장 | 인코딩이 몰래 바뀐다 |
| C. EUC-KR 인코더를 구현하거나 라이브러리 사용 | 변환표(약 17,000자) 때문에 번들이 커진다 |

### 패키지 위치

판단 로직은 ZIP과도 Monaco와도 무관한 순수 로직이므로 **`packages/file-kind`** 로 분리한다(ADR-0003의 패키지 목록에 추가).

```
packages/file-kind/src/
  index.ts        detectFileKind(name, head, totalSize) → FileKind
  signatures.ts   magic bytes 서명 표
  extensions.ts   확장자 표
  sniff.ts        BOM, NUL, UTF-8, 레거시 인코딩 검사
  decode.ts       인코딩별 텍스트 디코딩
```

판단 결과는 종류와 함께 **판단 근거(`reason`)** 를 담는다. 이 근거는 화면 안내와 테스트 검증에 쓴다.

```ts
type FileKind =
  | { kind: 'text'; encoding: 'utf-8' | 'utf-16le' | 'utf-16be' | 'euc-kr'; readOnly: boolean; reason: DetectReason }
  | { kind: 'image'; mime: string; reason: DetectReason }
  | { kind: 'binary'; reason: DetectReason };
```

## 근거

- **성능**: 판단 비용은 서명 비교, 표 조회, 8KB 한 번 훑기뿐이라 압축 해제 비용에 비해 무시할 만하다. 앞부분만 풀어 판단하므로 큰 바이너리를 통째로 풀지 않는다.
- **정확도**
  - 이미지·바이너리 서명은 텍스트에 나오지 않는 바이트로 설계되어 있어 가장 믿을 만한 신호다. 확장자가 틀린 파일도 잡는다.
  - NUL 검사는 Git(앞 약 8,000바이트)과 VS Code가 쓰는 방식이다. UTF-16 텍스트에는 NUL이 흔해 이 검사에 걸리므로, BOM 검사를 앞에 두어 보완한다.
  - UTF-8은 규칙이 엄격해 무작위 바이너리 8KB가 올바른 UTF-8일 확률은 사실상 0이다. EUC-KR 한글도 거의 항상 UTF-8 규칙을 어긴다. 따라서 "UTF-8 통과 = 텍스트" 판정은 믿을 만하다.

## 알려진 한계

- BOM 없는 UTF-16은 바이너리로 판정된다. 필요하면 "한 자리 걸러 NUL이 반복되는 패턴" 검사를 추가한다.
- EUC-KR 판정은 추정이라 Shift_JIS 같은 다른 레거시 인코딩과 완벽히 구분하지 못한다. 화면에 "추정"으로 표시한다.
- 앞 8KB 뒤에 바이너리가 섞인 파일은 텍스트로 판단될 수 있다. 전체를 풀어 디코딩할 때 다시 확인해, 바이너리가 나오면 바이너리로 바꾼다.

## 테스트

- 단계별 단위 테스트: 서명 표 전 항목, 8KB 경계의 한글, BOM 있는 UTF-8, 확장자·내용 충돌.
- **fuzz 테스트**(`fast-check`): 무작위 바이트가 텍스트로 오판되지 않는지, 무작위 문자열을 UTF-8로 인코딩한 값이 항상 텍스트로 판정되는지 검사한다.
- 실제 샘플 파일(`test/fixtures/`)

| 분류 | 샘플 |
|---|---|
| 이미지 | png, jpg, gif, webp, bmp, ico, svg |
| 바이너리 | pdf, zip, woff2, mp3, 실행 파일 조각 |
| 텍스트 | UTF-8 한글, UTF-8 BOM, UTF-16 LE/BE(BOM), EUC-KR 한글 |
| 경계 사례 | 확장자가 틀린 파일(`logo.txt`인 PNG), 확장자 없는 텍스트(`Makefile`), 빈 파일, 8KB 경계에 한글이 걸친 파일, 한 줄짜리 큰 minified JS |

이 샘플을 묶은 테스트용 ZIP을 E2E 테스트에도 쓴다.
