# ADR-0020. `cn()`은 clsx와 tailwind-merge로 만들고, shadcn의 `cn` 패키지는 쓰지 않는다

- 상태: 승인
- 날짜: 2026-09-27

## 배경

`cn()`은 여러 Tailwind 클래스를 합치면서 충돌하는 클래스(`px-4`와 `px-8` 등)를 정리하는 함수다. ADR-0002는 shadcn/ui의 방식대로 이 함수를 `clsx` + `tailwind-merge`로 만든다고 정했다.

shadcn CLI 4.21은 초기화할 때 이 두 패키지 대신, shadcn 팀이 만든 `cn` 패키지(0.4.0)를 설치한다. 패키지 설명은 "빠르고 작은, 미리 컴파일된 클래스 병합, clsx + tailwind-merge의 대체품"이다. 기본값을 따를지 기존 규칙을 지킬지 정해야 한다.

## 측정

`Button` 하나를 그리는 앱을 두 방식으로 각각 빌드했다. 두 방식이 만든 클래스 문자열은 시험한 모든 입력에서 같았다.

| 항목 | `cn` 패키지 | `clsx` + `tailwind-merge` |
|---|---|---|
| 빌드 JS (원본) | 253.38 KB | 254.78 KB |
| 빌드 JS (gzip, 실제 전송 크기) | 82.08 KB | **79.88 KB** |
| 호출 1회, 같은 입력 반복 | **0.12µs** | 0.31µs |
| 호출 1회, 캐시가 잘 안 맞는 입력 | **0.84µs** | 3.99µs |

실행 시간은 Node 24에서 20만 번 호출한 평균이다.

## 선택지

측정 결과를 놓고 두 가지를 비교했다.

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. `clsx` + `tailwind-merge` 유지 | gzip 전송 크기가 2.2KB 작다. ADR-0002와 shadcn/ui 방식 그대로다 | 호출이 0.2~3.2µs 느리다 |
| B. `cn` 패키지로 교체 | 호출이 2.5~4.7배 빠르다 | gzip 전송 크기가 2.2KB 크다. 미리 계산한 표가 들어 있어 압축이 덜 된다. shadcn/ui 방식과 달라진다 |

## 결정

**A를 택한다.** 속도 차이는 호출 한 번에 0.2~3.2µs라서 이 앱에서는 체감되지 않는다.

- React Compiler(ADR-0019)가 바뀌지 않은 컴포넌트의 렌더를 건너뛰므로 `cn()` 호출 자체가 적다.
- 파일 트리는 가상화해서 화면에 보이는 수십 줄만 그린다. 50줄을 다시 그려도 차이는 0.2ms 안쪽이다.
- 반면 전송 크기는 모든 사용자가 첫 방문 때, 그리고 새로 배포해 캐시가 무효화될 때마다 치르는 비용이다.

shadcn CLI로 컴포넌트를 추가하면 `import { cn } from "cn"`이 생길 수 있으므로, 추가한 뒤 `@/lib/utils`로 바꾼다.

## 결과

- shadcn/ui와 같은 구현을 유지한다.
- 클래스 병합이 실제 병목으로 측정되면 이 ADR을 다시 검토한다.
