# ADR-0025. 다운로드 기록을 내용 지문으로 남겨 새로고침 뒤에도 "받지 않은 변경"을 판정한다

- 상태: 승인
- 날짜: 2026-09-27
- 보완: ADR-0009, ADR-0014

## 배경

ADR-0009는 "마지막 다운로드 뒤에 또 고쳤는가"를 Monaco model의 버전 번호(`getAlternativeVersionId()`)로 판정한다. 다운로드할 때 "경로 → 버전"을 기록하고, 지금 버전과 비교한다. 한 세션 안에서는 정수 비교 한 번이라 빠르고 정확하다.

새로고침하면 이 방식이 깨진다. 두 가지 문제가 따로 있다.

- ADR-0014의 저장 항목에 다운로드 기록이 없어, 새로고침하면 "언제 무엇을 받았는지"가 사라진다.
- 다운로드 기록을 저장해 두더라도, 복원할 때 Monaco model을 새로 만들므로 버전 번호가 처음부터 다시 매겨진다. 내용이 받았을 때와 같은데도 기록과 번호가 다르다.

결과적으로 받은 뒤 새로고침만 해도, 원본과 달라진 파일이 모두 "받지 않은 변경"으로 잘못 표시된다.

## 선택지

복원 뒤 판정 방법으로 세 가지를 비교했다.

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. 다운로드 때 내용 지문(해시)을 저장하고 복원 뒤 비교한다 | 새로고침한 뒤에도 판정이 정확하다 | 지문 계산과 저장이 늘어난다 |
| B. 복원하면 전부 "받지 않은 변경"으로 본다 | 가장 단순하다 | 받아 놓고 새로고침만 해도 표시가 다시 뜬다. 사용자가 표시를 믿지 않게 된다 |
| C. 복원하면 전부 "받은 것"으로 본다 | 단순하다 | 정말 받지 않은 변경을 놓친다. 사용자가 받은 줄 알고 데이터를 지우면 작업을 잃는다 |

## 결정

**A를 택한다.**

- **다운로드할 때**: 수정된 파일은 어차피 `getValue()`로 내용을 읽는다(ADR-0006). 그 내용의 SHA-256 지문을 브라우저 내장 `crypto.subtle.digest`로 만들고, 경로별 지문과 그 시점의 구조(경로 목록)를 IndexedDB의 다운로드 기록에 저장한다. 원본 그대로인 파일은 ADR-0009대로 기록하지 않는다.
- **세션 안에서는**: 지금처럼 버전 번호로 비교한다. 지문은 판정에 쓰지 않는다.
- **복원할 때**: 복원한 파일 내용의 지문을 한 번 계산해 기록과 비교한다. 같으면 그 기록을 새 model의 현재 버전으로 옮기고, 다르면 "받지 않은 변경"으로 둔다. 구조는 저장된 경로 목록과 비교한다.

## 결과

- 받은 뒤 새로고침해도 "받지 않은 변경" 표시가 정확하다.
- 지문 계산은 다운로드와 복원 때만 일어나며, 수정된 파일에 한한다. 입력할 때는 비용이 들지 않는다.
- 라이브러리를 추가하지 않는다.
- 세션 안과 새로고침 뒤의 판정이 한 경우에서 다르다. 입력한 뒤 직접 지워 받은 내용과 같아진 파일은, 세션 안에서는 버전 번호가 달라 "받지 않은 변경"이지만, 새로고침 뒤에는 지문이 같아 "받은 것"이 된다. 새로고침 뒤의 판정이 내용 기준이라 더 정확하다. 세션 안의 차이는 입력할 때마다 내용을 비교하지 않기 위해 감수한다(ADR-0009와 같은 이유).
- 다운로드 → 새로고침 → 복원 → 판정 흐름과 "받은 뒤 고치고 새로고침" 흐름을 E2E 테스트로 확인한다.
