# ADR-0046. 사건 알림은 화면 아래에 떠 있는 알림으로 띄우고, 사용자가 닫는다

- 상태: 승인
- 날짜: 2026-09-29
- 보완: 업로드 오류, 큰 ZIP 경고, 다운로드 실패, Ctrl/Cmd+S 안내의 위치와 닫는 방법

## 배경

처음 설계는 업로드 오류를 업로드 영역 옆의 인라인 오류로 두었고, 큰 ZIP 경고·다운로드 실패·Ctrl/Cmd+S 안내의 위치는 정하지 않았다. 구현에서는 이 알림을 모두 상단 막대와 에디터 사이의 알림 줄에 넣었다.

운영 사이트에서 직접 써 보니 두 가지가 불편했다.

- 알림 줄은 상단 막대와 에디터 사이에 끼어 있다. 알림이 생기고 사라질 때마다 에디터가 아래위로 밀렸다. Ctrl/Cmd+S 안내는 2초 뒤 저절로 사라지므로, 단축키를 누를 때마다 에디터가 두 번 움직였다.
- 알림을 닫을 방법이 없었다. 업로드 오류는 다음 ZIP을 올릴 때까지 화면에 남았다. 알림 사이에 여백도 없어 답답해 보였다.

## 선택지

세 가지를 견주었다.

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. 알림 줄에 두고 여백과 닫기 버튼만 더한다 | 바뀌는 곳이 적다 | 알림이 생기고 사라질 때 에디터가 밀리는 문제는 그대로다 |
| B. 사건 알림을 화면 아래 가운데에 떠 있는 알림으로 띄우고, 닫기 버튼을 둔다 | 에디터를 밀지 않는다. 알림마다 닫을 수 있다 | 떠 있는 알림이 에디터 아래쪽 몇 줄을 잠깐 가린다 |
| C. B와 같이 띄우되, 모든 알림이 몇 초 뒤 저절로 사라진다 | 사용자가 닫지 않아도 된다 | 오류와 경고를 읽기 전에 놓치기 쉽다 |

## 결정

**B를 택한다.**

- **사건 알림**(업로드 오류, 큰 ZIP 경고, 다운로드 실패)은 화면 아래 가운데에 고정한 알림 목록에 쌓는다. 레이아웃 흐름 밖에 두어 에디터를 밀지 않는다. 목록의 빈 곳은 포인터 이벤트를 받지 않아, 알림 사이로 뒤의 에디터를 그대로 누를 수 있다.
- 사건 알림마다 닫기 버튼("알림 닫기")을 둔다. 오류와 경고는 사용자가 놓치지 않도록 시간이 지나도 저절로 닫히지 않는다. 다운로드 실패 알림에는 "다시 시도" 버튼도 둔다.
- 큰 ZIP 경고를 닫아도, 큰 ZIP이라는 표시(`largeZip`)는 그대로 둔다. 다운로드가 실패하면 실패 알림에 메모리 부족 안내를 덧붙여야 하기 때문이다.
- **Ctrl/Cmd+S 안내**도 같은 목록에 띄운다. 이 안내는 2초 뒤 저절로 사라진다. 닫기 버튼이 없고 포인터 이벤트도 받지 않는다.
- **상태 알림**은 지금처럼 상단 알림 줄에 둔다. 편집 잠금을 잃은 탭의 읽기 전용 안내와 저장 불가 배너가 여기에 해당한다. 이 두 알림은 한 번 일어난 사건이 아니라 지금 이 탭의 상태(편집할 수 없음, 저장할 수 없음)를 알리므로, 닫을 수 없고 상단에 남는다. 대신 위아래 여백을 준다.
- 알림 문구는 바꾸지 않는다. 새 문구는 닫기 버튼의 이름("알림 닫기") 하나다.

## 결과

- 알림이 생기고 사라져도 에디터가 움직이지 않는다. 390px 폭과 데스크톱에서 알림이 뜨기 전과 뜬 뒤의 에디터 위치가 같은 것을 확인했다.
- 떠 있는 알림이 에디터 아래쪽 몇 줄을 가릴 수 있다. 사건 알림은 닫으면 되고, Ctrl/Cmd+S 안내는 2초 뒤 사라진다.
