# ADR-0014. 작업 상태를 IndexedDB에 자동 저장하고, 잃을 수 있을 때만 이탈 경고를 띄운다

- 상태: 승인 (여러 탭 처리는 ADR-0024, 다운로드 기록 저장은 ADR-0025에서 보완)
- 날짜: 2026-09-27
- 일부 대체: ADR-0008의 이탈 경고 동작, ADR-0009의 `hasUnexportedChanges` 용도

## 배경

ADR-0008에서는 고친 내용을 메모리(Monaco model)에만 두고, 페이지 이탈 경고(`beforeunload`)로 작업 손실을 막기로 했다. 이 방식에는 두 가지 문제가 있다.

1. 브라우저가 강제로 종료되거나 탭이 튕기면 경고 없이 작업이 사라진다.
2. 요즘 브라우저는 `beforeunload` 경고창에 사이트가 정한 문구를 보여 주지 않는다. 사이트는 경고를 띄울지만 정할 수 있고, 문구는 브라우저 기본값("변경사항이 저장되지 않을 수 있습니다" 등)으로 나온다. ADR-0008의 "다운로드하지 않은 변경사항이 있습니다" 문구는 실제로 표시되지 않는다.

## 선택지

작업 상태를 브라우저에 남길지에 따라 두 가지를 비교했다.

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. IndexedDB에 자동 저장하고 다시 열면 복원한다 | 새로고침, 탭 튕김, 브라우저 종료 뒤에도 작업이 남는다 | 저장·복원 코드와 테스트가 늘어난다. undo 기록은 복원되지 않는다 |
| B. 메모리에만 두고 이탈 경고로 막는다 | 가장 단순하다 | 강제 종료 때 작업을 잃는다 |

## 결정

**A를 택한다.**

### 저장하는 것

| 항목 | 저장 시점 |
|---|---|
| 업로드한 ZIP 원본(Blob)과 파일 이름 | 업로드할 때 한 번 |
| 원본과 달라진 파일의 내용 | 아래 저장 규칙에 따라 |
| 트리 변경(추가·삭제·이름 변경) | 조작할 때마다 |
| 열린 탭과 분할 배치(dockview 레이아웃 JSON) | 레이아웃이 바뀔 때, 저장 규칙과 같은 방식으로 묶어서 |

안 고친 파일은 저장하지 않는다. 원본 ZIP에서 다시 꺼낼 수 있기 때문이다. 작업 공간은 한 번에 하나만 둔다.

### 저장 규칙 (타이핑 경로 밖에서)

ADR-0006의 "입력마다 `getValue()`를 부르지 않는다" 원칙을 지킨다.

- 입력이 멈추고 약 1초 뒤, 브라우저가 한가할 때 그 사이 바뀐 파일만 `getValue()`로 읽어 저장한다. 한가한 때는 `requestIdleCallback`으로 잡고, 이를 지원하지 않는 Safari에서는 `setTimeout`으로 대신한다.
- 탭이 숨겨질 때(`visibilitychange` → `hidden`)는 기다리지 않고 바로 저장한다. 모바일과 탭 전환에서는 `beforeunload`보다 이 이벤트가 더 확실하게 일어난다.
- `navigator.storage.persist()`로 브라우저가 저장소를 임의로 지우지 않도록 요청한다. 거절될 수 있으므로 결과에 의존하지 않는다.

### 복원

- 앱을 열 때 저장된 작업 공간이 있으면 "이전 작업을 이어서 할까요?"와 함께 ZIP 파일 이름, 마지막 수정 시각을 보여 주고, 이어 하기와 버리기 중에서 고르게 한다.
- 이어 하면 원본 ZIP을 다시 파싱하고, 저장된 트리 변경과 파일 내용을 적용하고, 탭과 레이아웃을 복원한다. 복원된 파일은 원본과 다르므로 수정 표시가 붙는다.
- undo 기록은 복원하지 않는다. Monaco에는 undo 기록을 밖으로 꺼내는 공개 API가 없기 때문이다.
- 새 ZIP을 업로드하면 기존 작업 공간을 대체한다. ZIP으로 받지 않은 변경이 있으면 먼저 확인한다.

### 이탈 경고

새로고침·닫기 경고는 변경이 IndexedDB에 저장됐는지에 따라 띄울지 정한다.

| 상황 | 새로고침·닫기 경고 |
|---|---|
| 모든 변경이 IndexedDB에 저장됨 | 띄우지 않는다 |
| 아직 저장되지 않은 변경이 있음 | 띄운다 |
| 저장이 실패했거나 저장할 수 없는 환경(시크릿 모드 제한, 용량 초과 등) | 띄운다. 화면에도 "이 브라우저에 저장할 수 없어 새로고침하면 작업을 잃습니다" 배너를 보인다 |

경고 문구는 브라우저 기본값이므로 따로 정하지 않는다.

### "ZIP으로 아직 받지 않음" 표시

ADR-0009의 `hasUnexportedChanges`는 이탈 경고 대신 **다운로드 버튼 옆 표시**(예: "받지 않은 변경 3개")에 쓴다. 데이터가 안전할 때마다 경고창을 띄우면 사용자가 경고를 무시하는 습관이 생긴다.

### 위치

저장소 접근은 `apps/web`의 services 계층에 둔다. IndexedDB는 얇은 래퍼 라이브러리 `idb`로 다룬다.

## 결과

- 새로고침, 탭 튕김, 브라우저 종료 뒤에도 마지막 저장 시점까지의 작업이 남는다.
- 타이핑 중에는 저장 작업이 일어나지 않는다. 저장 비용은 입력이 멈춘 뒤, 고친 파일에만 든다.
- 이탈 경고는 실제로 작업을 잃을 수 있을 때만 뜬다.
- 저장 실패, 복원, 버리기, 새 ZIP으로 교체하는 흐름을 E2E 테스트로 확인한다.
