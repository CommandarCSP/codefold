# ADR-0026. Monaco 언어는 전부 등록하고, 실제 규칙은 그 언어 파일을 열 때 불러온다

- 상태: 승인
- 날짜: 2026-09-27
- 보완: ADR-0021

## 배경

파일을 열면 확장자에 따라 문법 색칠이 자동으로 적용되어야 한다. ADR-0021은 번들 크기를 위해 Monaco에서 필요한 언어만 import하기로 했지만, 어떤 언어를 넣을지는 정하지 않았다. ZIP 안에 어떤 언어의 파일이 들어 있을지는 미리 알 수 없다.

Monaco의 언어 지원은 두 종류다.

- **언어 서비스**(TypeScript/JavaScript, JSON, CSS, HTML): 자동완성, 오류 표시, 정의로 이동을 제공한다. TypeScript는 컴파일러 전체가 들어 있어 크다. 각 서비스는 별도 Worker로 돌아간다.
- **문법 색칠**(81개 언어): 토크나이저 규칙만 있다.

`monaco-editor` 0.57을 열어 보면, 문법 색칠 언어는 `esm/vs/languages/definitions/<언어>/register.js`에서 다음처럼 등록된다.

```js
registerLanguage({
  id: 'python',
  extensions: ['.py', ...],
  loader: () => import('./python.js'),
});
```

등록 파일에는 언어 이름과 확장자만 들어 있고, 실제 토크나이저(`python.js`는 약 6KB)는 동적 import로 그 언어의 model이 처음 만들어질 때 불러온다. 81개 언어의 등록 파일을 모두 합치면 원본 20.1KB, gzip 2.9KB다(2026-09-27 측정).

## 선택지

어떤 언어를 등록할지 세 가지를 비교했다.

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. 언어 서비스 4종 + 문법 색칠 81개 전부 등록 | Monaco가 아는 확장자는 모두 색칠된다. 비용은 Monaco 청크 안의 등록 정보(gzip 2.9KB)뿐이다 | 등록 정보만큼 Monaco 청크가 조금 커진다 |
| B. 언어 서비스 4종 + 주요 언어 10개만 등록 | A보다 gzip 약 2.5KB 작다 | Kotlin, Ruby, PHP, Swift 같은 파일은 색칠 없이 열린다 |
| C. 언어 서비스 4종만 | 가장 작다 | 나머지는 일반 텍스트로 열려 대부분의 코드 파일이 색칠되지 않는다 |

## 결정

**A를 택한다.**

ADR-0021의 "필요한 언어만 import"와 부딪히지 않는다. 전부 들어가는 것은 언어 이름과 확장자를 담은 등록 정보뿐이고, 크기가 큰 토크나이저와 언어 서비스는 실제로 그 언어의 파일을 열 때만 불러오기 때문이다.

- 문법 색칠 언어 81개는 전부 등록한다. 등록 정보는 ZIP을 연 뒤 불러오는 Monaco 청크에만 들어가고, 첫 화면 번들에는 들어가지 않는다.
- 토크나이저는 그 언어의 파일을 처음 열 때 동적 import로 불러온다.
- 언어 서비스 4종의 Worker는 그 언어의 파일을 처음 열 때 만든다(ADR-0021의 Worker 주입 방식).
- 언어는 Monaco가 확장자와 첫 줄(`#!/usr/bin/env python` 같은 shebang)로 고른다. 81개 언어 어디에도 해당하지 않는 확장자는 일반 텍스트(`plaintext`)로 연다.

## 결과

- ZIP 안의 거의 모든 코드 파일이 색칠되어 열린다.
- 사용하지 않는 언어의 규칙과 Worker는 내려받지 않는다.
- 등록 정보와 언어별 청크 크기는 성능 리포트에 기록한다(ADR-0027).
