# ADR-0009. "원본과 달라짐"과 "다운로드 후 또 고침"을 따로 관리한다

- 상태: 승인 (`hasUnexportedChanges`의 용도는 ADR-0014로 일부 대체. 새로고침 뒤 판정은 ADR-0025에서 보완. 이벤트 시그니처는 `packages/react-code-editor` README가 최신)
- 날짜: 2026-09-27

## 배경

ADR-0008에서 다운로드는 저장이 아니라 현재 상태를 내보내는 동작으로 정했다. 수정 표시에는 두 가지 의미가 섞일 수 있다.

1. **원본과 달라짐**: 파일 단위. 트리·탭의 수정 표시, "변경 되돌리기", 다운로드 때 재압축할 파일 선택에 쓴다.
2. **마지막 다운로드 뒤에 또 고침**: 앱 전체 단위. 페이지 이탈 경고에 쓴다.

## 선택지

수정 표시의 두 의미를 나눌지 합칠지 두 가지를 비교했다.

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. 두 의미를 따로 관리한다 | 수정 표시는 항상 원본 기준이라 "무엇을 고쳤는지"가 언제나 보인다. 다운로드 직후에는 이탈 경고가 뜨지 않는다 | 기준값을 두 벌 관리한다 |
| B. 다운로드하면 기준을 새로 잡는다 | 기준값이 한 벌이다 | 원본과 다른데 수정 표시가 사라진다. "변경 되돌리기"의 목표(원본인지 다운로드 시점인지)와 재압축 대상 판단이 애매해진다. 사실상 저장 개념을 다시 들여온다 |

## 결정

**A를 택한다.**

### 비교 기준

model마다 `getAlternativeVersionId()` 값을 두 시점에 기록하고 현재 값과 비교한다.

| 기준 | 기록 시점 | 판정 |
|---|---|---|
| 원본 버전 | 파일을 처음 열 때 | 현재 ≠ 원본 → 원본과 달라짐 |
| 다운로드 버전 | 다운로드할 때 | 아래 규칙으로 이탈 경고 판정 |

### 다운로드 기록

"변경 되돌리기"는 model을 지우므로(ADR-0008), 다운로드 버전은 model이 아니라 **경로별 기록**으로 남긴다. 다운로드할 때 원본과 달라진 파일은 `경로 → 버전`을 기록하고, 원본 그대로인 파일은 기록하지 않는다.

이탈 경고(`hasUnexportedChanges`)는 다음 중 하나라도 해당하면 참이다.

- 기록에 있는 파일의 현재 버전이 기록과 다르다.
- 기록에 있는 파일이 원본으로 되돌려졌다.
- 기록에 없는 파일이 지금 원본과 달라져 있다.
- 파일·폴더 추가/삭제로 바뀌는 구조 버전이 기록과 다르다.

한 번도 다운로드하지 않았다면 기록이 비어 있으므로, 원본과 달라진 파일이 하나라도 있으면 참이다.

### 화면 동작

- 수정 표시는 다운로드해도 사라지지 않는다.
- 다운로드 버튼은 원본과 달라진 파일(또는 구조 변경)이 있으면 켜진다.
- undo로 다운로드했던 상태와 정확히 같아지면 이탈 경고가 저절로 꺼진다.

### 성능

- 판정은 `packages/editor`의 model 관리자 안에서 정수 비교로 끝난다.
- 밖으로 내보내는 이벤트는 `onDirtyChange(경로, 불리언)`과 `onUnexportedChange(불리언)` 두 가지이며, 값이 바뀔 때만 나간다.
- Zustand에는 `dirty[경로]`와 `hasUnexportedChanges`만 둔다. `beforeunload` 핸들러는 이 불리언 하나만 읽는다.

### 다운로드 시 내용 비교

버전 번호 비교는 "입력 후 직접 지워서 내용이 같아진 경우"도 수정으로 본다(VS Code와 같은 동작). 입력마다 전체 내용을 비교하지 않기 위한 선택이다. 대신 **다운로드할 때만** 수정 표시된 파일의 내용을 원본과 한 번 비교해, 실제로 같으면 재압축하지 않고 원본 압축 바이트를 복사한다.

## 결과

- 사용자는 "무엇을 고쳤는지"(수정 표시)와 "받아 두었는지"(이탈 경고)를 각각 정확히 알 수 있다.
- 기준값 두 벌과 경로별 다운로드 기록을 관리하는 코드가 필요하며, 위 판정 규칙을 그대로 단위 테스트로 옮긴다.
