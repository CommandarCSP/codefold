# ADR-0043. 운영 배포는 git 정보 없이 로컬 빌드 결과를 올린다

- 상태: 승인
- 날짜: 2026-09-29
- 일부 대체: ADR-0013의 "배포 (Vercel)" 절(`main`에 병합하면 운영 주소로, 기능 브랜치에 push하면 미리보기 주소로 배포한다)

## 배경

ADR-0013은 Vercel을 GitHub 저장소와 연결해, `main`에 병합하면 운영 주소로 자동 배포하기로 했다. 연결은 했지만 배포가 모두 막혔다(Blocked).

- Vercel 무료 요금제에서 비공개 저장소는 마지막 커밋의 작성자가 Vercel 계정 주인일 때만 배포할 수 있다.
- 이 저장소의 커밋 작성자 계정과 Vercel 계정 주인의 GitHub 계정이 다르다.
- 대시보드의 Redeploy도 같은 커밋을 다시 올리므로 막힌다. 저장소 안에서 Vercel CLI로 배포해도 CLI가 커밋 정보를 함께 보내므로 막힌다.

## 선택지

세 가지를 견주었다.

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. 로컬에서 빌드한 결과만 git 정보 없이 올린다 | 커밋 기록을 건드리지 않는다. 지금 계정과 요금제로 그대로 배포할 수 있다 | 배포를 사람이 직접 실행해야 한다. 브랜치별 미리보기 주소가 없다 |
| B. 이 저장소의 커밋 작성자를 Vercel 계정 주인으로 바꾼다 | 이후 커밋부터 자동 배포가 된다 | 커밋 기록에 작성자가 둘 섞인다 |
| C. 커밋 작성자 계정으로 Vercel 계정을 새로 만든다 | 자동 배포가 된다 | 운영 주소가 바뀐다. 계정과 프로젝트 설정을 처음부터 다시 해야 한다 |

## 결정

**A를 택한다.** 배포는 `pnpm deploy:prod`([scripts/deploy-prod.mjs](../../scripts/deploy-prod.mjs)) 하나로 한다.

1. 커밋하지 않은 변경이 있으면 배포하지 않는다. 그래야 운영 사이트가 어느 커밋에서 나왔는지 늘 알 수 있다.
2. `vercel build --prod`로 로컬에서 운영 빌드를 만든다.
3. 빌드 결과(`.vercel/output`)와 프로젝트 설정만 git이 없는 임시 폴더로 옮기고, 그 폴더에서 `vercel deploy --prebuilt --prod`로 올린다. 커밋 정보가 함께 올라가지 않으니 Vercel이 작성자를 검사하지 않는다.
4. 배포가 끝나면 운영 주소가 방금 빌드한 첫 화면 JS를 돌려주는지 확인한다.
5. 빌드 결과는 저장소에서 지운다.

- Vercel CLI는 늘 `npx vercel@latest`로 부른다. 오래된 CLI(28.x)는 Node 24 설정을 처리하지 못해 빌드가 실패한다.
- CI(ADR-0013의 "CI (GitHub Actions)" 절)는 그대로 둔다.

## 결과

이 결정으로 배포 방식이 다음처럼 바뀐다.

- 배포하려면 Vercel CLI에 Vercel 계정 주인으로 로그인해 두어야 한다(`npx vercel@latest login`).
- 브랜치별 미리보기 주소는 없다. 병합 전 화면 확인은 로컬 개발 서버나 로컬 미리보기 서버로 한다.
- GitHub 연동은 남아 있어 `main`에 push할 때마다 막힌 배포가 하나씩 생긴다. 이 기록은 무시한다.
- 커밋 작성자를 바꾸거나 유료 요금제로 옮기면 ADR-0013의 자동 배포로 돌아갈 수 있다. 그때는 이 ADR을 대체하는 새 ADR을 쓴다.
