# ADR-0006. 파일 내용의 원본은 Monaco model이고, React 상태에는 메타데이터만 둔다

- 상태: 승인 (에디터 인스턴스 수는 ADR-0007에서 "보이는 그룹마다 하나"로 조정)
- 날짜: 2026-09-27

## 배경

코드 에디터는 키를 빠르게 눌러도 느려지지 않아야 하고, 불필요한 렌더가 없어야 한다. 사용자가 입력할 때마다 바뀌는 파일 내용을 어디에 두느냐에 따라 이 두 항목의 결과가 갈린다.

Monaco의 `ITextModel`은 내부적으로 piece tree로 텍스트를 관리한다. 입력 한 번은 조각 하나를 추가하는 연산이라 파일 크기와 거의 상관없이 비용이 일정하다. 반대로 `model.getValue()`는 조각을 모두 이어 붙여 새 문자열을 만들기 때문에 파일 크기에 비례해 비싸다.

## 선택지

파일 내용을 어디에 두는지에 따라 두 가지를 비교했다.

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. Monaco model을 내용의 원본으로 두고, 상태 저장소에는 메타데이터만 둔다 | 입력마다 문자열 복사가 없다. 수정 여부가 바뀌는 순간에만 React 렌더가 일어난다. 파일별 undo 기록과 여러 파일 자동완성이 model 구조에서 자연스럽게 나온다 | 내용이 React 바깥에 있어 에디터 패키지 인터페이스를 거쳐 읽어야 한다 |
| B. 상태 저장소에 파일 내용 문자열을 두고 입력마다 갱신한다 | 흔한 방식이라 이해하기 쉽다 | 입력마다 `getValue()`로 전체 문자열을 만들고 구독 컴포넌트가 다시 그려진다. 파일이 크면 입력이 끊긴다. debounce로 줄이면 저장 시점 버그가 생기기 쉽다 |

## 결정

**A를 택한다.**

### 역할 분담

| 위치 | 보관하는 것 |
|---|---|
| Monaco model (`packages/editor`가 관리) | 파일 내용, undo/redo 기록, 언어, 버전 번호 |
| Zustand 스토어 (`apps/web`) | 파일 트리 메타데이터, 열린 탭 순서, 현재 탭, 파일별 수정 여부 |
| ZIP 원본 바이트 (`packages/zip`) | 원래 압축 데이터 |

### model 수명

- 파일을 처음 열 때 그 파일만 압축을 풀고 `monaco.editor.createModel(내용, 언어, Uri)`로 model을 만든다. 열지 않은 파일은 model이 없다.
- model URI는 ZIP 안 경로와 같은 `file:///경로` 형태로 만든다(`monaco.Uri.file()`). 공백·한글이 들어간 이름도 겹치지 않는다.
- 탭을 바꿀 때는 에디터를 다시 만들지 않는다. `saveViewState()` → `setModel()` → `restoreViewState()` 순서로 model만 갈아 끼워 커서·스크롤·접힘 상태를 복원한다.
- undo 기록은 model에 있으므로 탭을 오가도 파일별 undo가 유지된다.
- 파일을 삭제하면 model을 `dispose()`한다.

### 수정 여부 판단

- 파일을 열 때 `model.getAlternativeVersionId()`를 기준값으로 저장한다. 이 번호는 입력하면 바뀌고, undo/redo하면 이전 값으로 돌아간다.
- `model.onDidChangeContent`에서 "현재 번호 ≠ 기준값"을 계산하고, **이전 판단과 달라졌을 때만** 이벤트를 낸다.
- `apps/web`의 business hook이 이 이벤트를 받아 Zustand의 파일별 수정 여부를 갱신한다. 컴포넌트는 자기 경로의 값만 구독한다.

결과적으로 연속 입력 중 React 렌더는 파일이 처음 수정되는 순간과, undo로 원래 상태로 돌아가는 순간에만 일어난다.

### 에디터 패키지 인터페이스

`packages/editor`는 React에 의존하지 않는 model 관리자를 내보낸다. 밖에 보이는 인터페이스는 파일 열기, 내용 읽기, 수정 여부 확인, 닫기, 수정 여부 변경 구독 정도로 작게 유지한다. 구체적인 시그니처는 설계 문서에서 정한다.

### 여러 파일 자동완성 (Multi-model)

- TypeScript/JavaScript: Monaco의 TypeScript 언어 서비스(Web Worker)가 같은 언어의 model을 모두 한 프로젝트로 본다. URI가 실제 경로와 같으므로 `import ... from './utils'`가 다른 탭의 파일을 가리킨다. 그래서 함수·타입 자동완성과 오류 표시가 파일을 넘나들며 동작한다. 컴파일러 옵션(`allowJs`, JSX, 모듈 해석)을 맞춘다.
- 그 밖의 언어(Python 등): 언어 서비스가 없으므로 `wordBasedSuggestions: 'allDocuments'`로 열린 모든 model의 단어를 자동완성 후보로 쓴다.

### 다운로드

- model이 있고 수정된 파일만 `getValue()` → UTF-8 인코딩 → 재압축한다.
- 나머지 파일은 ZIP 원본의 압축 바이트를 그대로 복사한다(ADR-0001).

## 결과

- 입력 한 번의 비용은 Monaco 내부 연산과 정수 비교 한 번뿐이다. React DevTools Profiler로 연속 입력 중 커밋이 일어나지 않는 것을 확인할 수 있다.
- 비싼 `getValue()`는 다운로드할 때 수정된 파일에 한해 한 번씩만 호출된다.
- React StrictMode의 이중 마운트에서도 에디터 인스턴스가 하나만 있도록, 생성과 `dispose()`를 effect 정리 함수로 짝지어야 한다.
- Monaco는 매우 큰 파일(기본 약 20MB 이상)에서 토큰화 등 일부 기능을 자동으로 끈다. 이때 사용자에게 알리는 UI가 필요하다.
- 탭을 닫을 때 model을 남길지 지울지, 다운로드 후 수정 여부 기준값을 갱신할지는 별도 결정으로 다룬다.
