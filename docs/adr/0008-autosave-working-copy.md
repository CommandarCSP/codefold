# ADR-0008. 저장 개념 없이 고친 내용을 곧 작업본으로 삼는다

- 상태: 승인 (이탈 경고 동작은 ADR-0014로 일부 대체)
- 날짜: 2026-09-27

## 배경

ADR-0006에 따라 고친 파일 내용은 Monaco model에만 있다. 업로드한 ZIP 원본은 바뀌지 않고, 다운로드는 현재 상태를 새 ZIP으로 내보내는 동작이다.

VS Code 같은 데스크톱 에디터에는 디스크라는 별도 저장 장소가 있다. 그래서 안 고친 탭은 닫을 때 model을 바로 지우고, 고친 뒤 저장하지 않은 탭은 닫기 전에 저장 여부를 묻는다. 이 앱에는 디스크가 없으므로 고친 파일의 탭을 닫을 때 어떻게 할지 정해야 한다.

이 앱의 목적은 수정한 내용이 반영된 ZIP을 다시 다운로드하는 것이다. 파일마다 따로 "저장"할 대상이 있는 것은 아니다.

## 선택지

고친 파일의 탭을 닫을 때의 처리 방식으로 두 가지를 검토했다.

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. 저장(Ctrl+S) 개념을 두고, 저장하지 않은 탭을 닫을 때 확인한다 (VS Code 기본 방식) | 데스크톱 에디터 사용자에게 익숙하다. 닫으면 model을 항상 지운다 | 다운로드와 별개인 저장 단계가 하나 더 생긴다. "저장 안 한 수정"과 "원본과 달라진 저장본"이 나뉘어 수정 상태가 두 단계가 된다. 저장하지 않고 다운로드할 때의 동작이 애매하다. 닫으면 undo 기록이 사라진다 |
| B. 저장 개념 없이 고친 내용을 곧 작업본으로 삼는다 (VS Code Auto Save, 온라인 IDE 방식) | 수정 상태가 하나라 명확하다. 탭을 닫아도 고친 내용과 undo 기록을 잃지 않는다. "고치고 다운로드한다"는 흐름과 그대로 맞는다 | 고친 파일의 model은 탭을 닫아도 메모리에 남는다 |

## 결정

**B를 택한다.**

| 상황 | 동작 |
|---|---|
| 안 고친 파일의 탭을 닫음 | model과 뷰 상태를 지운다. 다시 열면 ZIP 원본에서 압축을 다시 푼다 |
| 고친 파일의 탭을 닫음 | 묻지 않고 model을 남긴다. 다시 열면 내용과 undo 기록이 이어진다 |
| 파일 트리에서 "변경 되돌리기" | 원본 내용으로 되돌리고 model을 지운다 |
| 수정된 파일이 있는 상태에서 페이지를 닫거나 새로고침 | `beforeunload`로 "다운로드하지 않은 변경사항이 있습니다" 경고를 띄운다 |

- 파일 트리와 탭에 수정 표시를 두어, 탭을 닫은 수정 파일도 트리에서 알아볼 수 있게 한다.
- 메모리에 남는 model은 "열린 파일 + 고친 파일"뿐이다. 고친 내용은 다운로드에 반드시 필요하므로 불필요한 메모리 사용은 없다.

## 결과

- 사용자가 고친 내용을 탭 닫기로 잃는 경우가 없다. 데이터가 사라질 수 있는 순간은 페이지 이탈뿐이며, 이를 경고로 막는다.
- 확인 대화상자가 없어 탭 닫기 흐름이 단순하다.
- 저장 개념이 필요해지면(예: 서버 저장 연동) 별도 ADR로 다룬다.
