# ADR-0005. 내부 패키지는 개발 중엔 소스를, 외부엔 빌드 결과물을 내보낸다

- 상태: 승인
- 날짜: 2026-09-27

## 배경

`apps/web`이 `packages/zip`과 `packages/editor`를 import할 때 어떤 파일을 읽을지 정해야 한다. 이 레포 안에서는 개발 속도가 중요하고, 레포 밖에서는 어떤 프로젝트든 설치해서 쓸 수 있어야 한다(ADR-0003).

## 선택지

검토한 선택지는 세 가지다.

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. 소스(`src/index.ts`)를 그대로 내보낸다 | 패키지를 고치면 앱 화면에 바로 반영된다(HMR). 빌드 단계가 없다 | 쓰는 쪽이 TypeScript를 직접 변환해야 한다. npm에 그대로 배포할 수 없다 |
| B. 빌드 결과물(`dist/`)만 내보낸다 | 어디서든 쓸 수 있는 라이브러리 형태다 | 개발 중 패키지를 고칠 때마다 다시 빌드해야 한다. watch 빌드를 따로 띄워야 한다 |
| C. 조건부 exports로 둘 다 내보낸다 | 레포 안에서는 A처럼 빠르고, 밖에서는 B처럼 쓸 수 있다 | `package.json` 설정이 조금 늘어난다 |

## 결정

**C를 택한다.** 각 패키지의 `package.json` `exports`에 사용자 정의 조건을 두어, 레포 안의 개발 환경은 소스를, 그 밖의 소비자는 빌드 결과물을 읽게 한다.

```jsonc
{
  "exports": {
    ".": {
      "source": "./src/index.ts",       // 레포 안 개발용 (Vite resolve.conditions에 추가)
      "types": "./dist/index.d.ts",
      "import": "./dist/index.js"
    }
  }
}
```

- `apps/web`의 Vite와 Vitest 설정에 `source` 조건을 추가해 소스를 바로 읽는다.
- 패키지는 ESM과 타입 선언 파일(`.d.ts`)로 빌드한다.
- `monaco-editor`처럼 앱과 한 벌만 공유해야 하는 라이브러리는 `peerDependencies`로 선언해, 쓰는 쪽이 버전을 정하고 번들에 두 벌이 들어가지 않게 한다.

## 결과

- 개발 중에는 패키지와 앱을 오가며 고쳐도 바로 반영된다.
- Turborepo의 `build` 작업이 패키지도 빌드하므로, **패키지가 배포 가능한 라이브러리 형태로 빌드되는지 CI가 매번 확인**한다.
- 조건 이름(`source`)을 쓰지 않는 외부 도구는 자동으로 빌드 결과물을 읽는다.
