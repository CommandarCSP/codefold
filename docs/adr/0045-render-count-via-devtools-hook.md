# ADR-0045. 렌더 횟수는 운영 빌드에서 개발자 도구 훅으로 센다

- 상태: 승인
- 날짜: 2026-09-29
- 일부 대체: ADR-0027 목표 표의 "키 입력당 React 렌더" 행의 검사 방법(React `<Profiler>`로 커밋 횟수를 세는 테스트 페이지)

## 배경

ADR-0027은 키 입력당 React 렌더 횟수를 "React `<Profiler>`로 커밋 횟수를 세는 테스트 페이지"에서 재기로 했다.

`<Profiler>`는 감싼 부분이 다시 그려질 때(커밋)마다 콜백을 부르는 React 컴포넌트다. 그런데 React 운영 빌드에서는 `<Profiler>`의 측정이 꺼져 있다. 이 방법을 쓰려면 `react-dom`을 측정 기능이 들어간 빌드(`react-dom/profiling`)로 바꿔 끼운 테스트 전용 진입점을 따로 만들어야 한다. 그러면 사용자가 받는 운영 빌드와 다른 코드를 재게 된다.

React는 운영 빌드에서도 커밋할 때마다 React 개발자 도구가 쓰는 전역 훅(`window.__REACT_DEVTOOLS_GLOBAL_HOOK__`)의 `onCommitFiberRoot`를 부른다. 그래서 성능 측정 코드를 이 훅으로 커밋 수를 세도록 만들었다. 이 결정을 ADR로 남긴다.

## 선택지

두 가지를 견주었다.

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. `<Profiler>`를 넣은 테스트 페이지(ADR-0027) | 컴포넌트별로 나눠 잴 수 있다. React가 공식으로 내놓은 측정 API다 | 측정용 빌드와 진입점을 따로 만들고 관리해야 한다. 운영 빌드와 다른 코드를 잰다 |
| B. 운영 빌드에 가짜 개발자 도구 훅을 심는다 | 사용자가 받는 운영 빌드를 그대로 잰다. 앱 코드에 측정용 코드가 들어가지 않는다 | 앱 전체의 커밋 수만 센다. 훅은 개발자 도구용 내부 약속이라 React가 바꿀 수 있다 |

## 결정

**B를 택한다.**

- 성능 측정(`apps/zip-editor/perf/perf.spec.ts`)은 페이지가 뜨기 전에 Playwright의 `addInitScript`로 가짜 훅을 심는다. 가짜 훅은 `onCommitFiberRoot`가 불릴 때마다 커밋 수를 하나 올리고, 나머지 메서드는 아무 일도 하지 않는다.
- 300줄짜리 TS 파일에 첫 글자를 입력한 뒤, 이어서 99글자를 입력하는 동안 커밋 수가 0인지 확인한다. 0이 아니면 실패한다.
- 첫 글자에서 커밋이 1회 이상 생겼는지도 확인하고, 0이면 실패한다. 훅이 작동하지 않으면 뒤의 검사가 늘 통과해 버리기 때문이다.
- 목표와 CI 처리(렌더 횟수는 실패, 시간 지표는 경고)는 ADR-0027 그대로다.

## 결과

- 측정 전용 빌드나 진입점을 두지 않는다.
- 앱 전체의 커밋 수만 알 수 있다. 어느 컴포넌트가 다시 그려졌는지 찾을 때는 React 개발자 도구의 Profiler 탭을 쓴다.
- React 버전을 올린 뒤 훅의 모양이 바뀌면 커밋 수가 늘 0으로 나와, 렌더가 늘어도 검사를 통과해 버릴 수 있다. 그래서 첫 글자 검사를 둔다. 첫 글자를 입력하면 파일이 수정됨 상태로 바뀌어 React가 반드시 한 번 커밋하기 때문이다.
