# ADR-0003. 모노레포로 코어·에디터·앱 패키지를 나눈다

- 상태: 승인 (ADR-0010에서 `packages/file-kind`, ADR-0016에서 `packages/workspace` 추가. 패키지 이름은 ADR-0023으로 일부 대체)
- 날짜: 2026-09-27

## 배경

코드 에디터는 ZIP 편집 말고도 코딩 실습, 코드 리뷰처럼 여러 화면에 쓰인다. 한 번 잘 만든 에디터와 Monaco 연결 코드를 여러 곳에 붙일 수 있게 앱과 에디터 사이의 경계를 먼저 정해야 한다.

## 선택지

재사용 경계를 실제 패키지로 나눌지, 폴더로만 나눌지 두 가지를 비교했다.

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. 모노레포로 패키지를 실제로 나눈다 | 재사용 경계를 코드 구조로 보여 준다. 패키지끼리 잘못된 방향으로 import하면 빌드에서 막힌다. 패키지마다 따로 테스트할 수 있다 | workspace와 TypeScript 설정에 초기 시간이 든다 |
| B. 앱 하나에서 폴더로만 나눈다 | 구조가 단순하고 설정이 빠르다 | 경계가 폴더 이름뿐이라 실수로 의존 방향을 어겨도 막을 장치가 없다. 재사용성은 문서로만 설명할 수 있다 |

## 결정

**A를 택한다.** 다음과 같이 나눈다. 패키지 이름 앞에 붙일 scope(`@<이름>/`)는 가칭이다.

```
packages/
  zip/      ZIP 읽기·쓰기와 파일 트리 구성. React도 Monaco도 모르는 순수 TypeScript
  editor/   Monaco 연결(model 수명 관리, undo/redo, 언어·테마 설정). React 없이도 쓸 수 있음
apps/
  web/      실제 애플리케이션. 앱 5계층 아키텍처 규칙은 여기에만 적용
```

의존 방향은 `apps/web → packages/editor`, `apps/web → packages/zip` 한쪽으로만 흐른다. React 전용 연결 코드가 여러 앱에서 필요해지면 그때 `packages/editor-react`를 추가한다.

## 결과

- "이 에디터를 다른 서비스에 붙이려면?"이라는 질문에 패키지 설치와 사용 예시로 답할 수 있다.
- `packages/zip`은 브라우저 API 외에 의존성이 없어서 Web Worker나 다른 프레임워크에서도 그대로 쓸 수 있다.
- 패키지 사이에 공유하는 TypeScript 설정은 루트의 기본 설정을 상속해 관리한다.
