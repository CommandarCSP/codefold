# ADR-0012. 파일 트리에서 추가·삭제·이름 변경을 지원하고, 옮기기는 넣지 않는다

- 상태: 승인 (확인창 관리 방식은 ADR-0035로 일부 대체)
- 날짜: 2026-09-27

## 배경

파일 트리에서 파일·폴더를 추가하고 삭제할 수 있어야 한다. 파일 트리에서 흔히 기대하는 이름 변경과 끌어서 옮기기까지 넣을지 정해야 한다.

제약이 하나 있다. Monaco model의 URI는 만든 뒤 바꿀 수 없다. ADR-0006에서 URI를 파일 경로로 정했으므로, 경로가 바뀌면 새 URI로 model을 다시 만들어야 한다. 이때 그 파일의 undo 기록은 이어지지 않는다. URI를 그대로 두면 undo는 남지만 경로가 실제 이름과 달라져, 다른 파일의 상대 경로 import 해석(여러 파일 자동완성)이 깨진다.

## 선택지

추가·삭제만 할지, 이름 변경과 옮기기까지 넣을지를 두고 세 가지 안을 비교했다.

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. 추가 + 삭제 + 이름 변경 | 파일 트리에서 기대하는 기본 조작을 갖춘다 | 이름을 바꾼 파일은 undo 기록이 끊긴다 |
| B. 추가 + 삭제만 | 작업량이 가장 적고 model URI 문제가 없다 | 이름을 잘못 지으면 지우고 다시 만들어야 한다 |
| C. A + 끌어서 옮기기 | 조작이 가장 자유롭다 | 옮기기는 경로를 바꾸는 일이라, 폴더를 옮기면 그 안의 model을 모두 다시 만든다. 트리 드래그 UI가 따로 필요하고 dockview 탭 드래그와 충돌하지 않게 조율해야 한다. 들이는 비용에 비해 얻는 것이 적다 |

## 결정

**A를 택한다.**

| 조작 | 동작 |
|---|---|
| 추가 | 선택한 폴더 안에 파일이나 폴더를 만든다. 같은 이름이 있거나 쓸 수 없는 문자가 들어가면 입력칸에서 바로 막고 이유를 보인다 |
| 삭제 | 폴더를 지우면 안의 파일도 모두 지우고, 열려 있던 탭을 닫고, 그 model을 `dispose()`한다. 고친 파일이 들어 있으면 확인창을 띄운다 |
| 이름 변경 | 새 경로로 model을 다시 만들고 내용과 수정 여부를 옮긴다. 열려 있던 탭은 새 model로 바꿔 연다. 그 파일의 undo 기록은 끊긴다 |

- 삭제만 확인창을 띄우는 이유: 탭 닫기는 고친 내용을 남기므로 묻지 않지만(ADR-0008), 삭제는 되돌릴 방법이 없다.
- 확인창은 nice-modal-react로 관리한다.
- 트리 구조가 바뀌면 ADR-0009의 구조 버전이 올라가고, 다운로드 버튼과 "받지 않은 변경" 표시(ADR-0014)가 이 값을 따른다.
- 다운로드할 때 새로 만든 파일은 새로 압축하고, 삭제한 파일은 결과 ZIP에서 뺀다. 이름을 바꾼 파일은 내용이 같으면 원본 압축 바이트를 새 이름으로 복사한다.

## 결과

- 이름 변경 뒤 undo 기록이 끊기는 동작은 VS Code와 같다. 이 동작은 사용자 문서에 적는다.
- 트리 조작마다 model, 탭, 수정 상태, 구조 버전이 함께 바뀌므로 조작 단위로 통합 테스트를 둔다.
- 끌어서 옮기기가 필요해지면 새 ADR로 다룬다.
