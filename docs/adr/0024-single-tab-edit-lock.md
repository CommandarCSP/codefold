# ADR-0024. 편집 권한을 브라우저 탭 하나에만 준다

- 상태: 승인
- 날짜: 2026-09-27
- 보완: ADR-0014

## 배경

ADR-0014에서 작업 상태를 IndexedDB에 자동 저장하고, 작업 공간은 한 번에 하나만 두기로 했다. IndexedDB는 같은 사이트의 탭끼리 저장소를 공유한다. 사용자가 앱을 탭 두 개로 열면 두 탭은 상대 탭이 무엇을 저장했는지 확인하지 않고 같은 저장본에 쓴다.

ADR-0014는 바뀐 파일만 저장하지만, 그래도 두 가지 경우에 한 탭이 다른 탭의 작업을 덮어쓴다.

- **같은 파일을 두 탭이 고칠 때**: 탭 A와 탭 B가 모두 `main.py`를 고치면, 나중에 저장한 탭의 내용만 남는다.
- **트리 변경 기록**: 탭 B가 `new.py`를 추가하고 저장한 뒤, `new.py`를 모르는 탭 A가 자기 트리 변경 기록을 저장하면 `new.py`가 저장본에서 사라진다. 열린 탭과 분할 배치(dockview 레이아웃)도 같은 방식으로 덮어써진다.

사용자는 작업이 사라진 줄도 모른다.

## 선택지

여러 탭을 어떻게 다룰지 세 가지를 비교했다.

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. 편집 권한을 한 탭에만 준다 | 덮어쓰기가 일어나지 않는다. 사용자가 권한을 옮길 수 있다 | 권한 이전 흐름을 만들어야 한다 |
| B. 막지 않는다 (나중에 저장한 쪽이 이김) | 가장 단순하다 | 작업이 조용히 사라진다 |
| C. 탭마다 작업 공간을 따로 둔다 | 탭마다 다른 ZIP을 편집할 수 있다 | ADR-0014의 "작업 공간은 하나"와 부딪힌다. 새로고침 때 어느 탭의 작업을 복원할지 정해야 한다 |

## 결정

**A를 택한다.** 브라우저의 Web Locks API(`navigator.locks`)로 편집 권한을 관리한다. 지원 브라우저(ADR-0030)가 모두 이 API를 지원한다.

### 잠금 얻기

- 앱을 열면 `ifAvailable: true`로 편집 잠금을 요청한다. 기본 요청은 잠금이 풀릴 때까지 기다리므로, 이 옵션을 써야 잠금을 얻었는지 곧바로 알 수 있다.
- 잠금을 얻은 탭만 편집하고 자동 저장한다.
- 잠금을 얻지 못한 탭은 "다른 탭에서 작업 중이에요" 안내와 "여기서 열기" 버튼을 보이고, IndexedDB에 쓰지 않는다.
- 잠금을 얻지 못한 탭은 뒤에서 한 번 더, 기다리는 요청을 걸어 둔다. 잠금을 쥔 탭이 닫혀 잠금이 넘어오면 안내가 "이제 이 탭에서 편집할 수 있어요"와 "편집 시작" 버튼으로 바뀐다. 사용자 모르게 화면이 편집 상태로 바뀌지 않도록 자동으로 전환하지 않는다.

### 잠금 가져오기

- "여기서 열기"를 누르면 `steal: true`로 잠금을 가져온다.
- 잠금을 빼앗긴 탭은 잠금이 풀렸다는 신호를 받아 곧바로 저장을 멈추고 읽기 전용 안내로 바뀐다.
- 잠금을 가져온 탭은 저장본을 다시 읽어 최신 상태에서 시작한다. 이때 빼앗긴 탭이 하던 저장이 아직 끝나지 않았을 수 있으므로, 빼앗긴 탭이 BroadcastChannel로 보내는 "저장 끝남" 신호를 최대 1초 기다린 뒤 읽는다. 신호가 오지 않으면 기다리지 않고 읽는다.

### 잠금 풀기

- 탭을 닫으면 브라우저가 잠금을 자동으로 푼다.

## 결과

- 두 탭이 같은 저장본을 덮어쓰는 경우가 없다.
- 권한을 빼앗긴 탭에 아직 저장되지 않은 변경이 있으면 그 변경은 사라진다. ADR-0014에 따라 입력이 멈추고 약 1초 뒤에 저장하고, 탭이 숨겨질 때는 바로 저장한다. 사용자가 다른 탭으로 옮겨 가면 숨김 저장이 먼저 일어나므로, 실제로 잃는 범위는 아직 저장되지 않은 마지막 입력뿐이다.
- 잠금 획득, 빼앗기, 탭 닫힘에 따른 넘겨받기 흐름을 E2E 테스트(브라우저 컨텍스트 두 개)로 확인한다.
