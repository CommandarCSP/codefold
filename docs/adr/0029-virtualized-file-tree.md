# ADR-0029. 파일 트리는 평평한 목록으로 바꿔 화면에 보이는 줄만 그린다

- 상태: 승인
- 날짜: 2026-09-27

## 배경

파일이 1만 개가 넘는 ZIP도 느려지지 않고 열려야 한다. ADR-0027은 1만 개 파일 ZIP의 트리를 1초 안에 보이게 하는 것을 목표로 정했다. 트리의 모든 행을 DOM에 그리면 폴더를 펼칠 때마다 수천 개의 요소가 생겨 느려진다.

트리 구조는 virtual-fs가 직접 만든다(ADR-0001, ADR-0016).

## 선택지

트리를 어떻게 그릴지 세 가지를 비교했다.

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. 트리를 평평한 목록으로 바꾸는 코드는 직접 쓰고, 보이는 행만 그리는 일은 `@tanstack/react-virtual`에 맡긴다 | 트리 로직을 직접 작성하라는 조건을 지킨다. 가상화 라이브러리는 UI가 없어(headless) 마크업과 접근성 속성을 우리가 직접 정한다 | 가상화 라이브러리 의존성이 하나 생긴다 |
| B. 가상화까지 직접 구현한다 | 의존성이 없다 | 스크롤 위치 계산, 가변 높이, 키보드 이동 시 스크롤처럼 까다로운 부분을 새로 만들어야 한다 |
| C. 트리 컴포넌트 라이브러리를 쓴다 | 가장 빠르게 만든다 | 라이브러리도 트리 구조를 만들어 virtual-fs와 역할이 겹친다 |

## 결정

**A를 택한다.**

### 목록 만들기와 그리기

- `virtual-fs`가 경로 목록으로 트리를 만든다(ADR-0016).
- `react-code-editor`가 펼친 폴더의 항목만 골라 평평한 행 목록(깊이, 경로, 종류)을 만든다. 폴더를 펼치거나 접을 때, 그리고 추가·삭제·이름 변경으로 트리 구조가 바뀔 때(ADR-0012) 이 목록을 다시 계산한다.
- `@tanstack/react-virtual`로 화면에 보이는 행과 앞뒤 여유분만 DOM에 그린다.

### 접근성

트리는 WAI-ARIA tree 패턴(`role="tree"`, `role="treeitem"`, `aria-expanded`, `aria-level`)을 따르고, 가상화 때문에 생기는 두 가지 문제를 이렇게 푼다.

- **포커스 관리는 `aria-activedescendant`로 한다.** 키보드 포커스는 트리 컨테이너에 두고, 활성 행은 `aria-activedescendant`로 가리킨다. 포커스를 행 요소 자체에 두는 roving tabindex 방식은, 사용자가 마우스 휠로 스크롤해 포커스된 행이 DOM에서 사라지면 포커스가 페이지 밖으로 빠진다. VS Code의 목록도 `aria-activedescendant`를 쓴다.
- **형제 수와 위치는 속성으로 알린다.** 형제 항목이 DOM에 다 있지 않으므로 행마다 `aria-setsize`와 `aria-posinset`을 달아, 스크린 리더가 "10개 중 3번째"를 읽을 수 있게 한다.
- 키보드로 화면 밖 행을 활성으로 옮길 때는 먼저 그 행까지 스크롤해 DOM에 그린 뒤 `aria-activedescendant`를 바꾼다.

## 결과

- 항목 수와 관계없이 DOM에 그리는 행은 화면에 보이는 만큼과 앞뒤 여유분뿐이다.
- 가상화 때문에 화면 밖 행은 DOM에 없으므로, E2E 테스트는 스크롤이나 트리 키보드 이동으로 행을 찾는다.
- 스크린 리더(VoiceOver, NVDA)로 트리 이동과 위치 안내를 확인한다.
