# ADR-0040. 이탈 경고는 레이아웃 변경을 세지 않고, 복원 실패 화면에서 새 ZIP을 열 때도 확인한다

- 상태: 승인
- 날짜: 2026-09-28
- 보충: ADR-0014

## 배경

ADR-0014는 작업 상태를 IndexedDB에 자동 저장하고, 저장되지 않은 변경이 있을 때만 이탈 경고를 띄운다고 정했다. 자동 저장은 편집 내용·트리 변경·다운로드 기록 말고도 탭 배치(레이아웃)를 저장한다. 저장되지 않은 것이 레이아웃뿐일 때 경고할지는 정하지 않았다.

복원 안내가 떠 있을 때 새 ZIP을 열면 확인창을 띄운다. 복원이 실패한 화면("다시 시도·버리기")에서 새 ZIP을 여는 경우는 정하지 않았다.

## 선택지

| 질문 | 선택지 | 장점 | 단점 |
|---|---|---|---|
| 저장 안 된 것이 레이아웃뿐일 때 | A. 경고하지 않는다 | 탭만 옮기고 곧바로 새로고침해도 경고가 뜨지 않는다 | 드물게 탭 배치 한 번이 저장되지 않는다 |
| | B. 경고한다 | 배치도 잃지 않는다 | 편집하지 않았는데 경고가 떠, 경고를 무시하는 습관이 든다 |
| 복원 실패 화면에서 새 ZIP | C. 확인한다 | 되살리지 못한 저장본이 사용자 모르게 사라지지 않는다 | 확인을 한 번 더 거친다 |
| | D. 확인하지 않는다 | 바로 연다 | 다시 시도하면 살릴 수 있던 저장본이 덮인다 |

## 결정

**A와 C를 택한다.**

- 이탈 경고의 "저장되지 않은 변경"은 편집 내용·트리 변경·다운로드 기록 가운데 아직 저장되지 않은 것이 있을 때만 해당한다. 레이아웃만 남았으면 저장된 것으로 본다.
- 복원 실패 화면에서 새 ZIP을 열 때도 복원 안내 때와 같은 확인창을 띄운다.

## 근거

- 이탈 경고는 잃으면 되살릴 수 없는 고친 내용을 지키려고 둔다. 탭 배치는 잃어도 다시 열면 된다.
- 복원 실패는 대개 일시적인 문제(저장소 잠김 등)라 다시 시도하면 살아날 수 있다. 새 ZIP을 열면 그 저장본을 덮는다.

## 결과

- 자동 저장 스케줄러는 대기 중인 저장에 레이아웃 말고 다른 것이 있는지를 따로 확인한다.
- 새 ZIP 교체 확인은 "복원 안내 중이거나 복원 실패 화면일 때"와 "받지 않은 변경이 있을 때" 띄운다.
