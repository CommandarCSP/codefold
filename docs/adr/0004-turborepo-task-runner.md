# ADR-0004. pnpm workspace 위에 Turborepo를 쓴다

- 상태: 승인
- 날짜: 2026-09-27

## 배경

ADR-0003에서 모노레포로 나누기로 했다. 모노레포에는 두 가지 일이 필요하다.

1. **패키지를 설치하고 서로 연결하는 일**: `apps/web`이 `packages/zip`을 import할 수 있게 한다.
2. **명령을 실행하는 일**: `build`, `test`, `lint`, `typecheck`를 의존 순서대로 실행한다.

1번은 패키지 매니저의 workspace 기능이 맡는다. 패키지 매니저는 pnpm을 쓴다. 2번은 별도의 작업 실행 도구를 쓸지 정해야 한다.

## 선택지

작업 실행 도구 없이 쓸지, 어떤 도구를 얹을지 세 가지를 비교했다.

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. pnpm workspace만 사용 (`pnpm -r`) | 가장 가볍다 | 결과 캐싱이 없다. 실행 순서를 스크립트로 관리해야 한다 |
| B. pnpm workspace + Turborepo | 의존 순서를 자동으로 정리하고, 병렬로 실행하고, 결과를 캐싱한다. 설정 파일 하나로 끝난다 | 도구가 하나 늘어난다 |
| C. pnpm workspace + Nx | 코드 생성, 의존 그래프 시각화 등 기능이 가장 많다 | 이 규모에는 무겁고 설정이 복잡하다 |

## 결정

**B를 택한다.** pnpm workspace가 패키지 설치와 연결을 맡고, Turborepo가 그 위에서 작업 실행을 맡는다. Turborepo는 패키지를 설치하거나 연결하지 않는다. 패키지 관계는 pnpm workspace 설정과 각 `package.json`에서 읽어 온다.

## 결과

- `apps/web`을 빌드하면 `packages/zip`, `packages/editor`가 먼저 빌드된다.
- 바뀌지 않은 패키지의 빌드·테스트 결과를 재사용한다. 앱만 고쳤다면 ZIP 파서 테스트는 다시 돌지 않는다.
- 지금은 패키지가 적어 속도 이득이 크지 않지만, 패키지가 늘어나거나 CI에서 원격 캐시를 붙일 때 지금 구성을 바꾸지 않고 확장할 수 있다.
