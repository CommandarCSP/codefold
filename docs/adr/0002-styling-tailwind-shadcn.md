# ADR-0002. 스타일링은 Tailwind CSS v4와 shadcn/ui로 한다

- 상태: 승인
- 날짜: 2026-09-27

## 배경

스타일링 도구를 정해야 한다. 흔히 쓰는 선택지는 Tailwind CSS 같은 유틸리티 CSS 프레임워크, CSS Modules, styled-components·emotion 같은 CSS-in-JS다. 다이얼로그·메뉴 같은 부품은 키보드 조작과 스크린 리더 지원까지 갖춰야 해서, 직접 만들기보다 검증된 접근성 부품을 쓰고 싶다.

이 앱에서는 성능, 특히 **빠른 타이핑 중의 반응성과 번들 크기**가 중요하다(ADR-0027).

## 선택지

세 가지를 CSS 번들 크기, 실행 중 비용, 접근성 부품을 얻는 비용을 기준으로 비교했다.

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. Tailwind CSS v4 + shadcn/ui | 빌드할 때 CSS를 만들고 쓰지 않는 클래스는 빠지므로 CSS 번들이 작다. 실행 중 비용이 없다. shadcn/ui(Radix)의 접근성 부품을 바로 쓴다 | 클래스 이름이 마크업에 길게 붙는다 |
| B. CSS Modules | 익숙한 CSS 문법 그대로 쓴다. 실행 중 비용이 없다 | 다이얼로그 같은 접근성 부품을 직접 만들거나, 스타일 방식이 다른 부품 라이브러리를 따로 맞춰야 한다 |
| C. styled-components / emotion | 컴포넌트와 스타일을 한 파일에 둔다 | 스타일을 실행 중에 만들어 렌더마다 비용이 붙고 번들이 커진다. 성능 목표와 맞지 않는다 |

## 결정

**A를 택한다.**

- Tailwind v4의 CSS 우선 설정(`@theme`)으로 디자인 토큰을 CSS 변수로 정의한다.
- 부품은 shadcn/ui(Radix Primitives 기반)의 코드를 프로젝트에 복사해 직접 관리한다.
- 클래스 병합은 `cn()`(clsx + tailwind-merge), 변형은 `cva`를 쓴다.
- 다크/라이트 테마는 CSS 변수 세트를 바꿔 끼우는 방식으로 하고, Monaco 에디터 테마도 같은 토큰에서 만든다.

## 결과

- CSS는 빌드 시점에 정적 파일로 만들어져 타이핑 중 스타일 계산 비용이 없다.
- 키보드 조작과 스크린 리더 지원은 Radix에 기본으로 들어 있다.
- 선택 이유(번들 크기, 실행 중 비용 없음)를 README에 적는다.
