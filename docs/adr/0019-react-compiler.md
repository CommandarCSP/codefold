# ADR-0019. React Compiler로 메모이제이션을 자동화한다

- 상태: 승인
- 날짜: 2026-09-27

## 배경

이 앱은 불필요한 렌더를 없애는 것을 성능 목표로 둔다(ADR-0027). React는 상태가 바뀐 컴포넌트와 그 자식을 다시 렌더링한다. 자식이 받는 props가 그대로여도, 부모가 렌더링될 때마다 객체와 함수가 새로 만들어지면 자식도 다시 그려진다. 이를 막으려면 `memo`, `useMemo`, `useCallback`을 알맞은 자리에 넣어야 한다.

손으로 넣으면 두 가지 문제가 생긴다.

- 빠뜨리기 쉽다. 의존성 배열 하나를 잘못 적으면 메모이제이션이 경고 없이 깨진다.
- 코드가 `useMemo`·`useCallback`으로 뒤덮여 읽기 어려워진다.

React Compiler는 React 팀이 만든 빌드 시점 컴파일러로, 1.0 정식 버전이 나와 있다. 컴포넌트와 훅을 분석해서, 값이 실제로 바뀔 때만 다시 계산하도록 메모이제이션 코드를 자동으로 넣는다. 수동 `useMemo`보다 더 잘게, JSX 조각 단위까지 메모이제이션한다.

## 선택지

메모이제이션을 누가 넣을지에 따라 두 가지를 비교했다.

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. 손으로 `memo`·`useMemo`·`useCallback`을 넣는다 | 동작이 코드에 그대로 보인다 | 빠뜨리거나 의존성을 잘못 적기 쉽다. 코드가 길어진다 |
| B. React Compiler를 켠다 | 빠뜨림 없이 자동으로 적용된다. 코드가 짧고 읽기 쉽다 | 빌드에 Babel 단계가 하나 더 든다. 컴파일러가 하는 일을 알고 있어야 디버깅할 수 있다 |

## 결정

**B를 택한다.** `apps/web`의 Vite 설정에서 `@vitejs/plugin-react`의 `reactCompilerPreset`을 `@rolldown/plugin-babel`로 적용한다. Vite의 `react-compiler-ts` 공식 템플릿과 같은 구성이다.

### 지켜야 할 규칙

컴파일러는 "React의 규칙"을 지키는 코드만 최적화한다. 규칙을 어긴 컴포넌트는 최적화를 건너뛰고(bail out) 원래대로 동작하므로, 틀린 결과를 내지는 않지만 성능 이득을 잃는다.

- 렌더링 중에 `ref.current`를 읽거나 쓰지 않는다. Monaco 에디터 인스턴스처럼 React 바깥의 가변 객체는 ref에 담고, effect와 이벤트 핸들러에서만 다룬다. ADR-0006에서 파일 내용을 React 바깥(Monaco model)에 두기로 한 구조와 잘 맞는다.
- 렌더링 중에 props나 state를 직접 바꾸지 않는다.
- `eslint-plugin-react-hooks` 7의 recommended 설정에 컴파일러 규칙 검사가 들어 있어, 위반을 린트에서 잡는다.

### 수동 메모이제이션

- 기본적으로 `useMemo`·`useCallback`·`memo`를 쓰지 않는다.
- 외부 라이브러리에 넘기는 콜백처럼 참조가 바뀌면 안 되는 곳에서만, 이유를 주석으로 남기고 쓴다.
- 특정 컴포넌트에서 컴파일러를 끄려면 `'use no memo'` 지시문을 쓰고 이유를 남긴다.

## 결과

- 렌더 횟수는 React DevTools Profiler로 측정하고, 최적화된 컴포넌트에는 DevTools에 "Memo ✨" 표시가 붙는지 확인한다.
- 빌드 시간이 조금 늘어난다. 측정값은 README의 성능 절에 남긴다.
- 코드 리뷰에서 "왜 `useMemo`가 없는가"라는 질문에는 이 ADR로 답한다.
